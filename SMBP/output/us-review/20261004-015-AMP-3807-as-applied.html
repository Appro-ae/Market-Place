Context of Business

Before a loan is disbursed, the users of the Ops Queue and the Fulfillment Queue confirm a list of checks. Each queue has a Maker and a Checker version, and each of the four queues has its own checklist. Disbursement Checklist lets the bank maintain these four checklists without a deployment.

Note: There is one set of checklists per bank, shared by all channels and loan products. The screen has no Channel dropdown and no product tabs. Updated 04/10/2026 (PO): Checklists are maintained per product type. The screen shows one tab per product type — same products and order as Document List ( AMP-3806 Ready for Dev ). Each queue has one checklist per product type. There is no Channel dropdown.

Navigation

  1. Login into Bank Portal.
  2. Click on “Document Management” in the left menu.
  3. Click on “Disbursement Checklist” (after “Document List”) to go to the Screen: Disbursement Checklist.

User Story

As a Bank Administrator,
I want to add, edit, activate, deactivate and delete the checklist items of each disbursement queue,
So that each queue shows the bank’s current checks before a loan is disbursed, without a deployment.

Checklist rules

  • Each queue has one checklist, shared by all loan products. Each queue has one checklist per product type.
  • The four queues are fixed. Only their items can be changed.
  • The list shows Active and Inactive items, in the order they were added.
  • Inactive rows are shown greyed out.
  • New items are added at the end.
  • The queue shows the Active items in the same order.
  • Duplicate texts are allowed. There is no limit on the number of items.
  • Only one row can be added or edited at a time.
  • Meanwhile, Add Checklist Item, Edit and Delete are disabled.

Default items

  • Each checklist starts with a set of default items.
  • The defaults are seeded on every product type tab (same list per product at go-live).
  • The bank can edit, deactivate or delete them like any other item.
  • Ops Queue Maker: 6 items, 2 optional. Example: “All pages uploaded and legible”.
  • Ops Queue Checker: 5 items, none optional. Example: “Employer, salary, amounts and IBAN match the application”.
  • Fulfillment Maker: 22 items, 11 optional. Example: “Payee is the lender — never the customer”.
  • Fulfillment Checker: 16 items, 2 optional. Example: “No lien or restraint on the account”.
  • The full default list is in the BDD attachment.

Optional items

  • An optional item can be left unticked in the queue.
  • It does not block Submit or Approve.
  • Items added on this screen are mandatory.
  • This screen has no control to make an item optional or mandatory.

How changes apply

  • An application keeps the checklist as it was when the application entered the queue.
  • A change applies only to applications that enter the queue afterwards.

When Checker Review is On (IA2)

  • Each change in AC2–AC5 becomes a request ( AC6).
  • It applies only after the checker approves it.

AC4. Activate and Deactivate a Checklist Item

  • A click on the Active toggle opens a confirmation pop-up.
  • An Inactive item stays in the list.
  • An Inactive item is not shown in the queue.

Deactivate pop-up (Active item)

  • Message: CM005 “Are you sure you want to deactivate this checklist item?”
  • Buttons: “Cancel”, “Yes, Deactivate”.

Activate pop-up (Inactive item)

  • Message: CM006 “Are you sure you want to activate this checklist item?”
  • Buttons: “Cancel”, “Yes, Activate”.

“Cancel” → close the pop-up; the status is unchanged.

On confirm — Checker Review Off

  • Apply the new status.
  • Deactivate: display IM034 “‘ {Checklist item}’ has been deactivated”.
    * Activate: display IM035 “‘{Checklist item}

    ’ has been activated”.

  • {Checklist item}

    = the item text.

On confirm — Checker Review On

  • Create an Update request ( AC6).
  • The status is unchanged until approval.
  • Display message “Your request for updated information is created successfully!”.

Audit: as in AC2, with [Step] = “Activate Checklist Item” or “Deactivate Checklist Item”.

AC5. Delete a Checklist Item

Confirmation pop-up

  • Title: “Delete checklist item?”
  • Message: CM011 “Are you sure you want to delete this checklist item?”
  • Buttons: “Cancel”, “Yes, Delete”.
  • “Cancel” → close the pop-up; nothing changes.

On “Yes, Delete” — Checker Review Off

  • Remove the item from the checklist.
  • The positions (#) are renumbered.
  • Display IM033 “Checklist item is deleted successfully!”.

On “Yes, Delete” — Checker Review On

  • Create a Delete request ( AC6).
  • The item stays in the list until approval.
  • Display message “Your request for updated information is created successfully!”.

Audit: as in AC2, with [Step] = “Delete Checklist Item” and [State] = “Deleted” (or “Pending Review”).

  • Each change is its own request.
  • Requests are raised per https://scvaladdin.atlassian.net/browse/ACP-245 AC3 under Module “Document Management / Disbursement Checklist”.
  • Requests carry no channel and no product type; they carry the product type and the queue.
  • Lock: while any request for a queue’s checklist is Pending Review or On Hold, that whole checklist is read-only. The lock applies per product type × queue checklist; the other product tabs stay editable.
  • Read-only = “Add Checklist Item”, Edit, Delete and the Active toggles are disabled.
  • The other queues’ checklists stay editable.

AC6.4 Checker Decision

Approve (https://scvaladdin.atlassian.net/browse/ACP-246 AC1)

  • Confirmation pop-up per https://scvaladdin.atlassian.net/browse/ACP-246.
  • Buttons: “Cancel”, “Yes, Approve”.
  • Create: the item is added at the end of its checklist, Active.
  • Update: the new text or status applies.
  • Delete: the item is removed; positions are renumbered.
  • Request Status = Approved.
  • Send ET28 to the maker.
  • Release the lock.

Reject (https://scvaladdin.atlassian.net/browse/ACP-246 AC2)

  • Confirmation pop-up per https://scvaladdin.atlassian.net/browse/ACP-246.
  • Buttons: “Cancel”, “Yes, Reject”.
  • The reason is mandatory.
  • The checklist is unchanged.
  • Request Status = Rejected.
  • Send ET27 to the maker.
  • Release the lock.

Expired (https://scvaladdin.atlassian.net/browse/ACP-246 AC3)

  • Same effect as Reject.
  • Request Status = Expired.
  • Send ET29 to the maker.

An approved change follows the AC1 “How changes apply” rule. Each decision is stored per CR 003.

Impact Analysis

IA1. Role Management

  • New permissions in Role Management, module “Document Management”, sub-menu “Disbursement Checklist”:
    • View Disbursement Checklist — see the screen and its four checklists;
    • Edit Disbursement Checklist — add, edit, activate, deactivate and delete items.
  • The permissions are bank-wide, not per product type.
  • Without Edit, “Add Checklist Item”, Edit and Delete are hidden.
  • Without Edit, the Active toggles are read-only.

IA2. Maker-Checker Configuration (https://scvaladdin.atlassian.net/browse/ACP-245)

  • Add “Document Management / Disbursement Checklist” to the Checker Review configuration table, with Yes / No.
  • Request types: as in AC6.1.
  • Add Create, Update and Delete of Disbursement Checklist to the Approving Authority Set in Checker Management (https://scvaladdin.atlassian.net/browse/ACP-247, https://scvaladdin.atlassian.net/browse/ACP-278).
  • The Maker Queue and Checker Queue screens themselves are unchanged.
