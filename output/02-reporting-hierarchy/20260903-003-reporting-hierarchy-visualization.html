User story (AMP-2548): As a bank portal administrator, I want to assign a Reporting Manager to each user and restrict enquiry screen visibility to direct reports, so that staff members see only their own assigned cases and managers see their direct reports' cases across Application Enquiry and Report Enquiry.

Three personas, three visibility outcomes

Staff-level user AC4

Sale code / staff ID matched against the application's Assigned To. Sees own cases only, applied as a pre-filter before channel / product / status / search filters. Empty result → IM005.

  • Gap: how a case gets Assigned To is not defined anywhere (R1)

Manager-level user AC5

Sees cases of the full reporting subtree — every user whose Reporting Manager chain leads to them — plus their own cases.

  • Gap: Context says "direct reports", AC5 says full subtree, mockup says 3 levels — pin one rule (R2)

Ops / Admin user Not in US

No assigned cases, no reports → sees nothing after this change. Today they see everything.

  • Proposed: "View All Applications" permission — same pattern as AMP-3323 "View All Application Sources" (R4)

CPO question — tag the case by Staff ID or UTM? The US filters on "Assigned To" but never defines how it is set. Below is the recommended capture design, built on what ADIB already runs in production journeys.

Capture channels → one person-level tag

Digital journey
UTM link parameter
Staff code carried as salesagentCode in the UTM URL, next to utm_source / medium / campaign. UTM analytics keeps working untouched.
ADIB-6725
Assisted journey
QR code scan
Customer scans the staff QR; code + branch details decrypted, every attempt stored with timestamp, latest successful wins.
ADIB-5651
Assisted journey
Manual code input
"Enter code or scan QR" — real-time validation, editable until Confirm.
ADIB-5651
Fallback
Round-robin default
No code from any channel → next active staff code from a DB config table (sequence, last-assigned flag, active flag). Every case ends up tagged.
ADIB-7172 · audit: ADIB-7237

The tag
Application · Assigned To = Staff ID (sale code)
Stored on the application record at submission · shown on Application Details · drives AC4/AC5 visibility and Report Enquiry scoping · audited.

Why Staff ID and not UTM as the assignment key

DimensionStaff ID / Sale CodeUTM (AMP-3323 — UAT Validated)
IdentifiesThe person who sourced / handles the caseThe marketing link and its owner — owner ≠ handling agent
Visibility modelDeterministic reporting line (RM hierarchy)Ownership + Share dialog (View/Edit, Everyone/specific) — changes with every share action
Unattributed casesRound-robin default → every case tagged"{Channel} Direct" fallback — visible to all enquiry users, breaking staff-only visibility
GranularityPerson-level — matches the CPO requirement exactlyLink-level — several staff can share one link; one owner runs many links
Role in target designThe assignment & visibility keyCarrier + campaign analytics — the URL transports salesagentCode; UTM reporting stays as built
Recommendation: Tag the case with Staff ID (sale code), captured via UTM parameter + QR + manual input + round-robin default (the ADIB pattern). Keep UTM for campaign analytics only. The Reporting Manager hierarchy then decides who sees whose cases.
