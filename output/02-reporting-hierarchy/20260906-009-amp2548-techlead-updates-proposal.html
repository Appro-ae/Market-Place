B · Best practice for a free-text Staff Code (what "free text" should mean)

"Free text" means the bank's legacy value is accepted as issued — it does not mean unvalidated. Every mature system keeps an employee identifier as a bounded, character-restricted text field with a normalised matching key: SAP personnel number is an 8-digit character field, Active Directory employeeID is capped at 16 characters, Salesforce User.EmployeeNumber is Text(20). ADIB itself stores it as free text and controls quality by an existence check against the bank's staff list, not by format.
#RuleWhyReferenceProposed wording for AMP-2548
B1Store as text, never as a numberLeading zeros and letters must survive: 003364 and ADIB001 are both live ADIB codes. A numeric column silently turns 003364 into 3364.ADIB-6681 ADIB-6811"Stored as a text value exactly as entered (after trimming); leading zeros are preserved."
B2Allowed characters: letters, digits and the separators - _ . /; no spaces, no other symbolsLegacy codes carry separators (STF-042, DSA/1355); anything beyond that is typo or injection surface — AMP-3583 flagged that the pop-up value is stored without validation today.AMP-3583"Accepted characters: A–Z, a–z, 0–9 and - _ . / . Internal whitespace and any other character are rejected with IEM005."
B3Length 1–24 charactersCovers every surveyed convention (SAP 8, AD 16, Salesforce 20, ADIB 4–7) and equals the pop-up limit, so any Staff ID can be typed by a customer. v4's 50 exceeds what the pop-up accepts.AMP-464 SAP Community · Microsoft Q&A · Salesforce Trailblazer"Length 1–24 characters."
B4Two representations: display value (as entered) and canonical key (uppercase, separators removed)The pop-up client strips non-alphanumerics (STF-042 → STF042) and UTM values are stored lowercase (IH14 §3.4). Uniqueness and matching must ignore case and separators or legitimate codes never match.AMP-3583 IH14 §3.4"Uniqueness (IEM001) and all matching use the canonical key = uppercase with separators removed; e.g. STF-042, stf_042 and STF042 are the same Staff ID. The display value is shown as entered."
B5Server-side validation of pattern and length on the user record and on the pop-up valueClient-only sanitising is bypassable; the same rule must apply at both entry points or attribution diverges.AMP-3583 AMP-3562"Validation runs server-side at save and at Checker approval; the Referral Code pop-up applies the same rule."
B6Quality control is an existence check, not a format checkADIB validates every typed code against the bank staff list in real time and lets the customer retry or skip. Format rules cannot catch a wrong-but-valid-looking code.ADIB-3755 ADIB-5651"The pop-up validates the entered value live against active Staff IDs (canonical key). Unknown code: 'Code not recognised — check with your salesperson or continue without.'" (v5 C2)
B7Mandatory for users in a restricted (Sales) department; optional otherwiseA Sales user without a Staff ID sees IM005 forever and cannot be in the round-robin pool. ADIB makes Employee ID mandatory for every user.ADIB-35"Mandatory when the user's Department is a restricted department; otherwise optional. Checked at save and at Checker approval, including when a user is moved into a restricted department."
B8Immutable once approved; corrections via a new record; case moves via ReassignThe code is the attribution key on every application; editing it silently orphans cases. Keep v4's rule, which is stricter than ADIB-45.v4 AC1 · v5 C7Unchanged v4 text.
B9No personal data as the codeThe value travels in URLs, QR codes and audit trails. Emirates ID, phone or e-mail as a Staff ID would leak PII on every link.Security hygiene (AMP-3583 review context)"Banks must not use national ID, phone or e-mail values as Staff IDs." (guidance note in AC1)
