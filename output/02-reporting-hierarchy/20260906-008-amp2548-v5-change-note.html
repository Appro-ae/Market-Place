B · How the v5 attribution flow reads (one paragraph for AC4)

  1. A Bank Portal user is created with a Staff ID (uppercase alphanumeric, ≤24, unique, read-only once approved).
  2. The Staff ID reaches the application in one of two ways: carried in the UTM link (optional parameter, Distribution Portal) or typed by the customer in the Referral Code pop-up (validated live against active Staff IDs).
  3. At submission the system resolves the tag: typed Staff ID → UTM Staff ID → sales round-robin (active users with a Staff ID, per channel/product, lowest attributed count, A→Z; default assignee if the pool is empty). Latest successful code wins; every attempt is audited.
  4. Every case created from go-live therefore carries a Staff ID. Unmatched or missing codes fall through to round-robin — nothing is left untagged; the raw code and an alert are kept for ops to investigate.
  5. Visibility follows the tag: staff see their own cases, managers their subtree, View-All roles everything; the "Assigned To (Sale Staff)" column, detail field and audit entry show who owns each case.
